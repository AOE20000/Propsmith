# 开发路线图

> **Propsmith** —— 以 MIT 协议发布的沙盒游乐场：生成道具、用工具改造世界、
> NPC 在街上过自己的生活、一切玩法面都向 Mod 开放。
> 复刻的是**经典沙盒游戏的玩法骨架**（物理抓取与冻结、约束建造、工具系统、
> 脚本 Mod 生态），全部原创实现，不使用任何第三方游戏的代码、模型或资产。
>
> 引擎 Godot 4.7 / Forward+ / Jolt Physics。单机优先，联机传输模块已就绪。

## 当前冲刺：精致的极小唯美画风开放世界 Demo

在 P0–P4 的骨架上做一个**小而完整、以观感为先**的可玩 Demo——体量控制在
「一张 160 m 见方的小世界、五到十分钟的一圈漫步」，但每一屏都要经得起截图。

- **M-A 观感基线**：✅ 已交付 —— `DemoLook` 模块（预设化的 Environment + 太阳：
  柔和暖色调、统一 ACES 色调映射与曝光、远景雾、bloom、SSAO、可选体积雾），
  日/黄昏/城市三套预设，`apply_to` 支持运行时换光；playground 水带升级为
  真实池塘（挖出池底形成水深）+ `water.gdshader`（顶点波纹、菲涅尔天空反射、
  按水深着色与透明度、岸边浪花）；plateau 接入同一基线的城市预设。
- **M-B 内容填充**：✅ 已交付 —— `src/world/decor.gd` 提供代码生成的唯美低模树/灯柱/
  长椅/石径/花丛（`Decor.tree/lantern/bench/stone_path/flower_cluster`），
  playground 按**种子确定性布局**摆放（石径沿一条 S 形曲线，灯柱/长椅跟着曲线走，
  树木与花丛用拒绝采样避开池塘、房间与走道）；`F4` 切换时段
  （`RenderDirector` 接管"地图的时辰"，与画风两条正交轴，换时段会把画风重新推导一遍）。
- **M-C 角色**：✅ 已交付 —— 地图建群默认改穿共享基准模型
  （`NpcFigure.default_appearance()` = `vrm`；`DSH_CITIZEN_APPEARANCE=capsule`
  可退回胶囊做对照）；新增 `tools/perf_probe` 做**实机帧成本测量**（关 vsync、关低功耗
  模式、统计分位）与 `DSH_PROFILE_FIGURE=1` 换装分解。
  **校准结论：阈值从来不是瓶颈。** 真正的 bug 是 `load()` 每次调用都重解析 61 MB 场景
  （380 ms/人 → 缓存后 4 ms/人），修掉之后城市 40 人只多 0.9 s 载入（且在加载屏后面）与
  **22 个 draw call**；「按距离延迟建造」被数据否决并删除——它会把隐藏的 0.9 s 变成
  开场可见的 40 次卡顿。数字留在 `npc_figure.gd` 的注释里，免得有人再建一遍。
- **M-D 声与拍**：✅ 已交付 ——
  **环境音**（开源素材，全部 **CC0**，来自 BigSoundBank/LaSonotheque，逐条来源与
  处理记录见 [`assets/audio/LICENSE_SOURCES.md`](assets/audio/LICENSE_SOURCES.md)）：
  `src/audio/ambience.gd` 挂在 `look_preset_changed` 上**随光照交叉淡化**（昼/昏各一床），
  水声作为 3D 点声源挂在池塘上按方位衰减；**电平按实测均值归一**（四条素材平均响度
  相差 13 dB，同一增益会让环境音每次换天都跳一下）。素材截取至 45 s 并加 20 ms 淡变、
  重编码 Vorbis，共 2.3 MB。
  **拍照模式**：`P` 隐藏全部界面，`F10` 把当前帧存到 `user://photos`；
  **滤镜就是画风**——`F2`/`F4` 在取景器里照常可用，Mod 注册的画风自动成为照片滤镜；
  不占用 `GameState.Mode`，因此与自由视角可共存，并在暂停等模式接管时自动让出界面。
  `look_probe` 的出图也改走 `PhotoMode.capture()`，于是每轮探针都在端到端验证这条路径。
- **遗留**：「开场镜头」小序列未做（M-D 的第三项，优先级最低）；city 地图尚无
  夜间床（`dusk` 会回落到 default 床）。
- **验收**：十张随机截图无需修饰即可作为宣传图；集成显卡稳定 60 FPS；
  冷启动到可玩 ≤ 30 秒。

## 已交付阶段（存档）

### P0 沙盒地基 ——「能生成、能抓、能冻、能删」

- 道具系统：目录（箱/球/板/坡道/桶…，全部代码构建网格）+ 工厂 + 生成菜单，
  Mod 可经 `ModContext` 注册道具。
- 物理扳手 v1：射线抓取、投掷、冻结/解冻、旋转；移除与撤销栈。
- 验收：无头测试生成 50 个道具不失败；冻结态物理静默；删除后引用干净。

### P1 工具系统 ——「改造世界的语法」

- 工具框架：射线命中 → 工具回调；工具为注册点，Lua Mod 与核心同权。
- 首批工具：焊接、绳索、轴与铰链、球窝/滑轨、复制器、移除/上色/配重。
- 验收：焊接联动、绳索吊装、轴上转轮、Mod 注册的工具进入轮盘。

### P2 NPC 与人流 ——「街上有人在过自己的生活」

- 市民生成器 + 标签驱动人流接通（种子确定的日程行走）。
- 市民可伤害/可击杀；无地点表地图优雅降级并报告原因。

### P3 Mod 全面化 ——「沙盒的灵魂」

- 道具、工具、NPC 类型、日程模式全部走 `ModContext` / `ScriptBridge`。
- 验收：纯 Lua Mod 新增工具与道具并进入生成菜单与轮盘。

### P4 地图与内容 ——「开局沙盒图与城市」

- Playground 开局图（草地/白盒/水域）作为第二 `MapSource`；渋谷城市图保留。
- 实体组合存档（决定式：存蓝图而非物理状态）。

### 基础设施（2026-10 追加）

- **画风（渲染风格）注册点**：渲染成为可被 Mod 接管的玩法面。画风是对地图自身气氛的
  **可逆覆盖**（预设 + 覆盖表，经 `DemoLook.apply_to` 一次写回全部键），于是切换画风 =
  重新推导，无需保存/还原，任何画风（含「切回写实」）都必然收敛回同一个样子。
  内置 `写实` 与 `3渲2`；`F2` 切换；Mod 经 `add_render_style` /
  `add_render_style_preset` 注册，脚本 Mod 走数据式。屏幕空间通道画在跟随当前相机的
  `ScreenPass` 四边形上（`canvas_item` 读不到深度缓冲），并采用**叠加**而非整帧替换
  （3D 材质的屏幕纹理只含不透明阶段，替换会抹掉水等透明面）。
  样板：`mods/render_style_demo/`（黄金时刻 = 纯数据；黑白电影 = 自带着色器）。
- **决策日志（DecisionLog）**：全部离散世界变更（生成/移除/上色/配重/外观）
  经统一服务入 JSONL 日志；加载 = 快照 + 重放；保存即压实；自动保存去抖。
- **共用基准角色管线**：SiroinoSotai（CC0）躯干 + Akane（CC0）头部的合成基准
  模型；玩家与市民共用；九条形体滑条 + 九件服装开关 + 市民外观编辑
  （交互入口 + 决策持久化）。
- **行走动画**：开放动画库（CC-BY）骨骼重定向；速度驱动的播放与步幅。
- **按需渲染**：距离剔除、阴影纪律、站姿写入距离门——远端市民近乎零成本。

### 联机（模块已交付）

- **ENet 传输模块**：主机权威星型拓扑；离散决定广播/提交/中继；迟到者追赶
  （沙盒快照 + 未覆盖日志重放）；玩家位置中继（12 Hz）。
- **已验证**：双进程探针——决定到达主机并入库、迟到者追赶后世界一致、
  全程零脚本错误。
- **待接**：联机界面（建主机/加入）、远端玩家的基准模型渲染与外观同步。

## 技术决定（不变项）

- **场景在代码里构建**，`.tscn` 只挂脚本；无头测试四件套是唯一合并门槛。
- **模块只经 `Services` / `Events` 通信**；每个玩法面先长出 Mod 注册点，再长核心实现。
- **GDExtension 一律 `ClassDB` 探测 + `Variant`**，绝不写进 `project.godot`。
- 存档只存「决定」+ `map_id`；世界由地图源重建。
- **MIT 发布**：本项目代码 MIT；第三方资源保留原许可（见 README 许可表）；
  **不引入任何 GPL/AGPL 代码或其衍生资产**（同类开源项目的架构思想可借鉴，
  代码不可复制）。
