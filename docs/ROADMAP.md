# 开发路线图：MIT 协议的沙盒游乐场

> 定位：一个**以 MIT 协议发布**的沙盒游乐场——生成道具、用工具改造世界、
> NPC 在街上过自己的生活、一切玩法面都向 mod 开放。
> 复刻的是**经典沙盒游戏的玩法骨架**（物理抓取与冻结、约束建造、工具系统、
> 脚本 mod 生态），全部原创实现，不使用任何第三方游戏的代码、模型或资产。
> 玩法对照与操作细节见本地参考（不入库）。
>
> 单机优先。引擎 Godot 4.7 / Forward+ / Jolt Physics。

---

## 当前冲刺：精致的极小唯美画风开放世界 demo

在 P0-P4 的骨架上做一个**小而完整、以观感为先**的可玩 demo——体量控制在
「一张 160m 见方的小世界、五到十分钟的一圈漫步」，但每一屏都要经得起截图。

- **M-A 观感基线**：WorldEnvironment 全面调校（柔和暖色调、远景雾、bloom、
  可选体积雾）、色调映射与曝光统一；水面反射（playground 的水带升级为
  反射/波纹着色器）。
- **M-B 内容填充**：唯美低模树/灯笼/长椅/石径（程序化生成 + 摆放场景），
  草地点缀花草簇；白天/黄昏两种光照预设。
- **M-C 角色**：批量市民换 VRM 外观（性能预算内扩量）、玩家接 Configura
  模型（Blender 管线已通）、市民行走动画（VRMA 或程序化摆动）。
- **M-D 声与拍**：环境音（风/水/鸟）、拍照模式（隐藏 UI + 滤镜）、
  一个「开场镜头」小序列。
- **验收**：十张随机截图不需要任何修饰即可作为宣传图；帧率在集成显卡
  上稳定 60；冷启动到可玩 ≤ 30 秒。

## P0 沙盒地基 —— 「能生成、能抓、能冻、能删」

沙盒的第一分钟是：呼出生成菜单，点一个箱子，用**物理扳手**拎起来，冻在半空。

- **道具系统**：`PropDef` 目录（箱/球/板/坡道/桶…，全部代码构建网格），RigidBody + 质量/材质。
- **生成菜单**：快捷键呼出，分类浏览 + 点击生成在准星落点；**mod 可注册道具**（走 `ModContext`，与现有 vehicle/poi 注册同缝）。
- **物理扳手 v1**：射线抓取（临时 joint 持有、跟随准星、滚轮推拉距离）、左键投掷、右键冻结（`freeze = FREEZE_MODE_STATIC` + 视觉提示）、解冻（再抓取 / R 键，含解除相连组）；按住交互键旋转抓取物（吸附角度可配置）。
- **移除与撤销**：对准删除；生成/操作栈 undo（Z）。
- **验收**：无头测试能 spawn 50 个道具不炸；冻结态物理静默；删除后引用干净；undo 栈正确回滚。

## P1 工具系统 —— 「改造世界的语法」

- **工具框架**：射线命中 → 工具回调（命中实体/点/法线/玩家输入）；工具是**注册点**（`add_tool`），Lua mod 与核心同权；工具参数走上下文面板。
- 首批工具（约束以 Jolt joint 实现）：
  - **焊接**（两实体间 `Generic6DOFJoint3D` 全锁，参数：力上限，可解除）
  - **绳索**（`DampedSpringJoint3D`：长度/弹性可调，渲染线绳）
  - **轴与铰链**（`HingeJoint3D` + motor：车轮/门）
  - **球窝 / 滑轨**（`Generic6DOFJoint3D` 角限位 / `SliderJoint3D`）
  - **复制器**（把一组实体+约束序列化成"蓝印"，一键重放——与实体存档同构）
  - **移除 / 上色 / 配重 / 无碰撞**（改 layer 对）
- **验收**：焊接两箱拖动一个带动另一个；绳索吊起道具；轴上装轮转起来；复制一套斜坡结构；一个 Lua mod 注册的工具出现在轮盘里。

## P2 NPC 与人流 —— 「街上有人在过自己的生活」

- **NPC 生成器**：菜单生成人形 NPC；**标签驱动人流接通**——NPC 按活动日程（家→公司→吃饭→家）在地图上行走（`PedestrianAgent` 已就绪）。物理扳手可放置 NPC 但不可冻结（与道具规则区分）。
- **地点表导出修复**：`tools/city_export_activity` 对渋谷的大文件（~65 MB/个）导出卡住待查——小文件秒级完成，需定位是文件规模、appearance 引用还是与编辑器并发的资源锁；修通后 `activity.json` 落地，`MobilityReadiness` 报告人群质量。
- **NPC 可伤害/可击杀**（接 `Damageable`），死亡即移除（NPC 战斗沙盒起点）。
- **验收**：街上 40 个 NPC 按种子确定的日程行走；被攻击会死；帧率达标；无地点表地图上 NPC 优雅降级（站着不动并报告原因）。

## P3 Mod 全面化 —— 「沙盒的灵魂」

- **玩法面全注册点化**：道具、工具、NPC 类型、日程模式全部走 `ModContext` / `ScriptBridge`（Lua mod 与 GDScript mod 同权）。
- **addons 目录约定**：清单 + lua/gd 入口，向社区使用习惯靠拢；双加载器分工不变。
- **验收**：一个纯 Lua mod 新增一种工具 + 一种道具，且出现在生成菜单与工具轮盘里。

## P4 地图与内容 —— 「开局沙盒图与城市」

- **经典开局图**：平坦草地 + 白盒建筑 + 水域，纯代码构建，作为第二 `MapSource`——mod 也可以注册自己的地图。
- **渋谷城市图保留**（城市沙盒 + 人流的展示舞台），含 SDK 可选降级。
- **实体组合存档**：生成/焊接/约束/复制的世界状态进存档（decision-based：存实体蓝印而非物理状态）。
- **远期（不承诺时间）**：NPC 战斗 AI、载具生成菜单、多人模式、玩法模式（如道具伪装、推理对局——mod 生态的方向展示）。

## 技术决定（不变项）

- **场景在代码里构建**，`.tscn` 只挂脚本；无头测试四件套是唯一合并门槛。
- **模块只经 `Services` / `Events` 通信**；每个玩法面先长出 mod 注册点，再长核心实现。
- **GDExtension 一律 `ClassDB` 探测 + `Variant`**，绝不写进 `project.godot`、绝不写成类型。
- 存档只存「决定」+ `map_id`；世界由地图源重建。
- **MIT 发布**：本项目代码 MIT；第三方资源（godot-plateau、godot-mod-loader 等）保留原许可，见 README 许可表；**不引入任何 GPL 代码**（同类开源项目的架构思想可借鉴，代码不可复制）。
